# Save (บันทึกงานค้าง — ถาวร, แยกตามโปรเจค)

เก็บ "บันทึกงานค้าง" ไว้ **1 ไฟล์ต่อ 1 โปรเจค** เพื่อให้ทำงานต่อได้ลื่นข้าม session.
คำสั่งเดียวใช้ได้ทั้ง **เซฟ** (ตอนจบงาน) และ **โหลด/ต่อ** (ตอนเริ่มงานใหม่) — สกิลจะ
ตัดสินเองจาก argument และจากว่ามีงานเกิดขึ้นใน conversation นี้แล้วหรือยัง.

> ใช้ไดเรกทอรี/ไฟล์เดียวกับสกิล `handoff` เดิม (`~/.claude/handoffs/`) — ของที่
> `/handoff` เคยเซฟไว้ `/save` โหลดต่อได้เลย และกลับกัน.

## Step 1 — หาไฟล์ของโปรเจคนี้

ทำก่อนเสมอ. ไฟล์ผูกกับ root ของโปรเจค (git top-level ถ้ามี ไม่งั้นใช้ cwd) จึงเป็น
ไฟล์เดียวกันไม่ว่าจะอยู่ subfolder ไหน.

```bash
HANDOFF_DIR="$HOME/.claude/handoffs"
mkdir -p "$HANDOFF_DIR"
ROOT="$(git rev-parse --show-toplevel 2>/dev/null || pwd)"
SLUG="$(printf '%s' "$ROOT" | sed 's#^/##; s#[/ ]#-#g')"
SAVE_FILE="$HANDOFF_DIR/$SLUG.md"
if [ -f "$SAVE_FILE" ]; then
  echo "STATUS=EXISTS"
  echo "MTIME=$(date -r "$SAVE_FILE" '+%Y-%m-%d %H:%M')"
else
  echo "STATUS=MISSING"
fi
echo "FILE=$SAVE_FILE"
echo "ROOT=$ROOT"
```

## Step 2 — เลือกโหมด

- argument เป็น `save`, `end`, `stop`, `write`, `เซฟ`, `บันทึก`, `จบ`, `พัก`
  → **SAVE (เซฟ)**.
- argument เป็น `load`, `resume`, `start`, `read`, `open`, `ต่อ`, `อ่าน`, `โหลด`
  → **LOAD (โหลด)**.
- ไม่มี keyword ชัดเจน → ตัดสินอัตโนมัติ:
  - ถ้าไฟล์ **มีอยู่แล้ว** และ conversation นี้ **ยังแทบไม่มีงานจริง** (เพิ่งเริ่ม
    session ใหม่) → **LOAD**.
  - กรณีอื่นทั้งหมด (มีงานเกิดขึ้นจริงใน session นี้ หรือยังไม่มีไฟล์) → **SAVE**.
- argument ที่เป็นข้อความอิสระ (ไม่ใช่ keyword) ให้ถือเป็นคำอธิบายว่ารอบหน้าจะโฟกัส
  อะไร — เก็บไว้แล้วปรับเนื้อหาตอน SAVE ให้สอดคล้อง. ตอน LOAD ใช้ bias ว่าจะหยิบส่วนไหน
  มาทำต่อ.

บอกโหมดที่เลือกสั้นๆ 1 บรรทัดก่อนลงมือ.

> หมายเหตุ: ถ้าเพิ่งเซฟไปและ **ยังไม่มีงานใหม่** ตั้งแต่นั้น ไม่ต้องเขียนทับซ้ำเปล่าๆ —
> บอกผู้ใช้ว่าไฟล์ปัจจุบันอยู่แล้ว.

## Step 3a — LOAD (โหลด / ต่อ)

1. อ่านไฟล์ด้วย Read tool.
2. บรีฟผู้ใช้แบบกระชับ: ทำอะไรไปแล้ว, ค้างตรงไหน, step ถัดไปทันที, และ blocker/
   decision ที่ค้าง. อย่าเทเนื้อหาทั้งไฟล์.
3. ตรวจก่อนเชื่อ: เอกสารสะท้อน ณ ตอนที่เขียน. ถ้ามันอ้างไฟล์/branch/flag/คำสั่ง ให้
   เช็คว่ายังมีอยู่จริงก่อนแนะนำให้ทำ.
4. ถ้ามีหัวข้อ "Suggested skills" ในไฟล์ ให้เรียกสกิลนั้นถ้าเข้ากับงานที่กำลังทำต่อ.
5. **ห้ามเขียนทับไฟล์ในโหมด LOAD.** แล้วทำงานต่อ.

## Step 3b — SAVE (เซฟ / เขียนทับ)

เขียนเอกสารไปที่ `$SAVE_FILE` **ทับของเดิม** (ไม่เก็บ history — ไฟล์ล่าสุดคือ
แหล่งความจริง). เขียนให้ agent ที่ไม่มี context มาก่อนเลยหยิบทำต่อได้ทันที. ใช้โครงนี้:

```markdown
# Handoff — <ชื่อโปรเจค>
_Saved: <YYYY-MM-DD HH:MM> · Branch: <git branch> · Session focus: <arg หรือที่อนุมานได้>_

## State of play
ย่อหน้าเดียว: ตอนนี้งานอยู่ตรงไหน.

## Done this session
- สิ่งที่ทำเสร็จ (อ้างอิง commit/PR/path — อย่าวาง diff).

## In progress / next step
- งานถัดไปที่สำคัญที่สุด 1 อย่าง แล้วตามด้วยที่เหลือเรียงตามความสำคัญ.

## Open decisions & blockers
- อะไรที่ยังค้าง ต้องตัดสินใจหรือปลดล็อกก่อน.

## Key context not in the repo
- ข้อเท็จจริงที่ไม่ชัดในโค้ด, gotcha, ความแปลกของ env. อ้าง PRD/plan/ADR/issue ด้วย
  path หรือ URL แทนการก๊อปมาวางซ้ำ.

## Suggested skills
- สกิลที่รอบหน้าควรเรียก และเพราะอะไร.
```

กฎตอน SAVE:
- **อย่าซ้ำ** เนื้อหาที่มีใน PRD/plan/ADR/issue/commit/diff อยู่แล้ว — อ้าง path หรือ URL.
- **ปกปิดความลับ** — API key, password, token, ข้อมูลส่วนตัว ห้ามเขียนลงไฟล์เด็ดขาด.
- เขียนเสร็จ ยืนยัน absolute path กลับให้ผู้ใช้ 1 บรรทัด.
